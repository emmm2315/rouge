# 项目检查与重构记录

验证环境：Windows，Oracle JDK 25.0.2，Maven Wrapper 3.8.5，编译目标 Java 21。

## 已复现并修复

- 新局未清理待执行交互：旧局调用 requestInteract 后立即重开，会在新局首帧自动拾取物品。新增测试在修改前失败（预期 0 金币，实际 7），修复后通过。
- 换层重置近战计数却未同步会话快照：下一帧被当作一次影斩，错误触发夜行披风。新增测试在修改前失败（预期速度 230，实际 271.4），修复后通过。
- 暂停清理此前只覆盖控制器按键，模型中的待执行交互、冲刺及蓄力边沿可能残留。现在统一清理待执行输入，取消未发射蓄力及格挡窗口；已获得的强化攻击保留。新增回归测试覆盖取消后不扣能量、不发射、不冲刺、不拾取，以及再次按下能够蓄力。

## 重构范围

- 抽出 PlayerStanceSystem，集中管理光形态蓄力、影形态格挡及按键边沿；模型仍不依赖 JavaFX。
- GameSession 分离换房初始化和战斗事件结算，保持原有更新顺序与奖励规则。
- GameController 统一重开和停止时的输入清理，初始化复用 newRun，统一难度和瞄准初始化。
- 删除会话中已经废弃的 combatActive 注释代码。

## 剩余维护事项

- GameRenderer、EnemySystem 仍是体积很大的类；后续可分别按 HUD/实体绘制与敌人物种行为拆分。本次聚焦已验证的会话生命周期问题，未重写全部渲染和敌人 AI。
- JDK 25 对现有 Maven/JavaFX 依赖输出 native-access 与 Unsafe 弃用警告，本次没有阻断构建或启动。Java 21 运行环境尚未单独复测。
- README 中死亡结算快捷键说明与当前 GameController 的 R/M 行为不一致，需要以产品规则决定最终统一方向。
- 测试、构建和运行需要访问用户 Maven 缓存；受限环境首次执行 Wrapper 时缓存路径解析到 C:/.m2，使用正常本机环境后可运行。
